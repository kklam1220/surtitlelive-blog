**Core summary:** AI can accelerate script preparation and translation drafting. It cannot turn an unreviewed document into performance-ready surtitles. A dependable workflow keeps every transformation visible, editable, rehearsable, and owned by a person.

The useful alternative to PowerPoint is not simply “the same slides, generated faster.” It is a production workflow that connects the source script, translation decisions, cue structure, rehearsal changes, audience delivery, and live operation.

That difference matters because the difficult part of surtitling is rarely placing text on a screen. It is maintaining a trustworthy relationship between what the artists are doing now and what the audience is being asked to read.

## Start by Defining the Audience Service

Before importing a script or choosing an AI model, define what the text is for.

- Is it a translation into another language?
- Is it same-language accessibility captions?
- Does it need speaker identification or meaningful sound information?
- Will the audience read a shared projection, a personal device, or both?
- Which seats, devices, and audience groups must the design serve?
- Who has editorial authority, and who will operate the live cues?

These are production decisions, not software settings. They determine how lines should be written, timed, displayed, tested, and supported.

“Professional surtitles” should not mean polished-looking text with no accountable process behind it. It should mean that the service has a defined audience, reviewed content, rehearsed operation, and a realistic recovery plan.

## Step 1: Preserve the Source Before You Transform It

A theatre script is a structured document, not a bag of sentences. Character names, dialogue, stage directions, scene headings, indentation, and spacing may all carry meaning.

Keep an authoritative source copy and record its version before processing it. If the production team changes the script later, you need to know which text the surtitle draft came from.

SurtitleLive can import `.docx` scripts and prepare an editable cue draft. Its analysis uses document structure and classification to identify likely dialogue and other line types. That output is a starting point for review, not a claim that every theatrical format will be parsed perfectly.

Check:

- Were cast lists or front matter mistaken for dialogue?
- Were character names separated correctly from their lines?
- Did stage directions remain identifiable?
- Were poems, songs, simultaneous speech, or speakerless passages handled as intended?
- Are any pages, tables, or unusual layouts missing?

Automation is valuable here when it makes the source easier to inspect—not when it hides uncertainty.

## Step 2: Build Cue Units for Reading, Not for Document Fidelity

A line in a script is not automatically a good surtitle. Page layout serves readers; cue structure serves an audience watching a live event.

In the editor, teams can revise text and prepare cue units by merging, splitting, or reordering lines. The objective is not to reproduce every document boundary. It is to create readable units that preserve meaning and can be operated against performance timing.

Review:

- whether each cue expresses one coherent thought;
- whether line breaks support syntax and emphasis;
- whether names or labels are necessary for the intended service;
- whether dense passages need editorial shortening;
- whether a split would reveal a joke or response too early;
- whether the cue order still matches the current rehearsal script.

Keep the transformation reversible. When a cue differs substantially from the source, the team should still be able to trace why.

## Step 3: Use AI Translation as a Drafting Stage

Once the source and cue structure are stable enough to work with, AI-assisted translation can reduce the time required to produce a first pass.

SurtitleLive’s editor-time translation workflow can use surrounding lines and saved character-name terminology while generating drafts. The resulting text remains editable. It is not live speech translation, and it does not guarantee the preservation of voice, rhyme, historical register, humour, or dramaturgical intent.

Give the review to someone who can compare the source and target language. Ask them to check more than grammar:

- character voice and relationships;
- deliberate ambiguity and repeated imagery;
- names, pronouns, titles, dialect, and register;
- omissions, additions, and over-explanation;
- cultural references and wordplay;
- reading density and performance timing.

If a language cannot receive competent review, do not present the presence of an AI-generated track as equivalent to a finished audience service.

## Step 4: Separate Content Approval from Cue Timing

Text can be linguistically approved and still fail in performance. Timing requires a different pass.

During rehearsal:

1. Run cues against actual delivery rather than an imagined reading pace.
2. Watch the stage and text together from representative audience positions.
3. Check projected and mobile output separately if both are offered.
4. Revise cues when blocking, pauses, cuts, or line order changes.
5. Mark the version that has been approved for live use.

There is no universal characters-per-second value that makes every production readable. Language, audience, complexity, display, and purpose all matter. Measurement can reveal pressure; rehearsal determines whether the service actually works.

This is also where the operator learns the production. Cueing is not a clerical click-through. The operator reads performance rhythm, recognizes departures, and decides how to recover without sending the audience further out of sync.

## Step 5: Design for Deviation

Static slide decks often assume a linear show. That can be perfectly workable when the performance is stable and the operator knows the deck. Problems appear when the system gives the operator no clear way to respond to a skipped line, repeated section, late start, or emergency cut.

A live surtitling workflow should make navigation and recovery deliberate:

- the operator can identify the current cue quickly;
- moving to another cue does not require searching through an opaque file;
- late script changes are incorporated into one approved version;
- the team has agreed what to do when a line is skipped or repeated;
- projection, mobile delivery, and any external show-control path have each been rehearsed;
- a fallback remains available when the preferred output or connection fails.

Dedicated software can make these actions easier. It cannot recover the show on behalf of an unprepared team.

## Step 6: Choose Outputs Without Creating a Second Source of Truth

Different productions need different outputs. A team may use SurtitleLive for live projection or an audience browser, export an `.xlsx` file for review, or create a `.pptx` when a slide-based handoff is genuinely the right choice.

The important question is not whether PowerPoint is permitted. It is which version remains authoritative.

If text is edited independently in several exported files, corrections drift. If the show returns to a slide deck for a venue handoff, establish a version label and decide whether later changes will be made in the editor, the deck, or both. Avoid a rehearsal process in which no one can say which file contains the approved wording.

An export is a delivery artifact. It should not quietly become an unmanaged second editorial system.

## A Practical Readiness Gate

Before the audience enters, confirm:

### Content

- The source version is identified.
- Parsing and cue boundaries have been reviewed.
- Every offered language has an accountable reviewer.
- Translation and accessibility-caption requirements are distinguished.
- The live version is marked and late changes are controlled.

### Audience experience

- Text has been viewed from representative seats and devices.
- Instructions explain where and how the audience will read.
- Brightness, line length, font size, and sightlines have been checked in the room.
- An alternative exists for people who cannot use the planned personal-device path.

### Operation

- The operator has rehearsed the show, not only the interface.
- Skips, repeats, jumps, pauses, and ending states have been practised.
- Every delivery path has a named owner.
- The fallback is usable and has been tested.

If one of these sections is incomplete, more automation does not make the production ready.

## Beyond PowerPoint Means Beyond a File

PowerPoint can display surtitles. For some shows, it remains a practical tool. The reason to adopt a dedicated workflow is not that slide software is inherently unprofessional.

The stronger reason is that a live text service benefits from:

- one traceable source;
- reviewable automation;
- language and cue decisions that remain editable;
- rehearsal-linked revisions;
- deliberate audience delivery;
- operator recovery when performance deviates.

AI can reduce mechanical preparation. Software can connect the stages. Professional practice comes from the people who review, rehearse, and take responsibility for the result.
